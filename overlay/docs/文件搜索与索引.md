# 文件搜索与索引

## 文件已经存在，却搜不到

`Ctrl+Shift+N`（或普通模式按 `空格 f f`）按文件名搜索，使用 fd 扫描目录，不依赖 clangd 索引。底部显示“索引就绪”不会改变文件搜索的过滤规则。

文件搜索默认包含隐藏文件，以及被 `.gitignore`、`.ignore`、`.fdignore` 等规则忽略的文件，排除 `.git` 元数据和各层目录中的 `.cache/clangd/index` 内部索引缓存。生成的头文件、忽略目录内的源码、普通文本文件均可搜索，不需要重新编译或重建符号索引。

- 在文件搜索框按 `Alt+I`，可以切换是否包含忽略项。切换为遵守忽略规则后，大型构建目录内的文件会被过滤；下一次新开文件搜索恢复默认的完整范围。
- 默认不递归进入软链接目录。在搜索框按 `Alt+F` 可以切换跟随软链接；链接指向很大的外部目录时，搜索范围和扫描工作量会增加。指向单个文件的软链接本身可以搜索。
- 搜索范围为当前工作目录。可用 `:pwd` 确认；建议通过 `astronvim /实际项目根目录` 打开整个项目。
- 新建文件后重新打开文件搜索即可重新扫描，无需等待符号索引。

这次调整只影响按文件名搜索。资源管理器和关键词搜索保留各自的过滤规则；关键词搜索侧栏的文件类型筛选也保持独立。

## 与符号搜索的区别

`Ctrl+N` 查询函数、类等符号，需要 clangd 正确读取项目的 `compile_commands.json`。索引只覆盖其能够正确解析的代码，不是磁盘文件清单。编译数据库目录配置见 [编译数据库目录配置](clangd-cdb-env.md)。

如果按文件名可以打开源码，但 `Ctrl+N` 搜不到其中的函数，应通过 `:LspInfo` 和 `:LspLog` 检查编译数据库、宏、头文件路径和解析错误。文件名搜索的这个修复不会改变或重建符号索引。
