# 持续输出、日志与连接中断

## 程序输出

原生 GDB 的 stdout/stderr 以 DAP 输出事件到达。旧实现每收到一段输出，就拼接全部历史并重写整个 Console，耗时会随历史输出增长。

当前实现由 `config/nvim/lua/debug_console.lua` 逐段追加，保留未结束的行、中文、空段和末尾换行。仅在切换调试会话或重建已删除的 Console 缓冲区时恢复完整历史。Attach 完成/失败提示使用同一路径。不会截断输出，也不改变 `set print elements 0`。

在实际 Windows VS Code → PowerShell → SSH → Linux 链路中，同一个原生 GDB 测试程序输出 12,000 行，约 0.97 MB：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 全量重写 Console 次数 | 12,087 | 1（初始化） |
| 输出处理累计时间 | 约 169 秒 | 约 0.32 秒 |
| 输出内容核对 | 最终一致，但交互请求超时 | 与收到的 DAP 输出逐字节一致 |

“输出处理累计时间”不等于程序运行总时间。测试程序自身包含等待，修复后的完整测试约 6.4 秒。此结果针对持续程序输出，不代表无限长变量求值、数据库业务执行或 ARM 硬件性能。

已验证分段/多行/中文输出、会话切换、Console 删除后恢复，以及 GDB/CodeLLDB 连续切换。完整验收记录随交付目录提供；每条记录注明平台、测试范围和未覆盖项。

后续在同一实际客户端链路连续运行 30 分钟：360,000 行 stdout，加上 stderr 共 29,211,616 字节，与捕获的 DAP 输出 SHA256 完全一致；每 10 秒打开并关闭搜索，共 180 次，响应约 50～123 毫秒。首次长测搜索等待超时，随后观察到终端处于命令行历史窗口；原因未完全确定，失败记录保留；第二次增加焦点和模式状态检查后通过。该结果覆盖 30 分钟，不外推为数小时或任意输出量保证；测量进程包含测试脚本额外保留的输出副本。

## clangd 日志

两种架构的配置均使用标准 LSP `positionEncodings` 协商字符位置，移除了旧 `offsetEncoding` 扩展参数。已使用实际 clangd 验证：函数声明和定义前包含中文及非 BMP 字符时，代码跳转仍落在正确字节位置。

Neovim 可能把语言服务器的所有 stderr 内容包装成 `[ERROR]` 写入 `lsp.log`。应继续阅读内层消息：clangd 的 `I[...]` 通常是信息，`E[...]`/`W[...]` 及具体诊断才说明需要排查的问题。不要仅按外层标签判断，也不要忽略实际错误。

运行日志路径和临时 TRACE 的启用方法见 [README 日志目录与错误记录](../README.md#日志目录与错误记录)。默认不启用详细通信追踪，以免增加正常使用开销。

## 迁移到较深目录

已复现 Neovim 的 Lua 缓存文件名过长问题：插件源码路径被编码成单个文件名，超过 Linux 文件名长度限制时，界面初始化报 `ENAMETOOLONG`。

共同运行时 `opt/nvim/share/nvim/runtime/lua/vim/loader.lua` 对这类长名称使用源码路径 SHA256 作为缓存键；短名称和原有缓存失效规则保持不变。普通目录使用 Neovim 内嵌加载器；数据、配置或运行时目录编码后超过 150 字节时，`config/nvim/init.lua` 才加载修订后的运行时。该判断为本包 Lua 文件的相对路径和扩展名预留了 105 字节，已核对当前文件集合。

普通加载继续使用字节码缓存；在不能调用 Vimscript 哈希函数的 libuv 快速回调中，首次长路径加载直接读取源码，后续普通加载会建立缓存。修复不依赖 CPU 架构。额外手动安装到其他超长路径的插件不属于本次路径集合验收范围。

## SSH 静默断网

正常点击退出按钮时，远端能发送终端清理序列，Windows 组件同时恢复原快捷键文件。若网络只丢包且没有立即断开 TCP，SSH 需要先检测连接失效。

客户端可在连接命令中指定心跳，例如：

```powershell
ssh -o ServerAliveInterval=10 -o ServerAliveCountMax=3 user@host
```

测试使用独立 SSH 服务，客户端和服务端均设置了 2 秒心跳、2 次重试。运行中和暂停时的静默丢包测试均验证了：编辑器退出、GDB 释放目标、目标继续运行、Windows 快捷键文件精确恢复。未配置心跳时，不保证同样快地发现断网。

断网可能阻断终端清理序列，使原 PowerShell 标签仍保留远端的屏幕或键盘模式。快捷键文件恢复与终端显示状态是两件事。此时在 VS Code 中新建终端后再连接；不要把残留的调试界面当作仍在连接的会话。本工具不会为清理屏幕而向用户现有 shell 自动发送命令，也不会自动关闭该 shell。
