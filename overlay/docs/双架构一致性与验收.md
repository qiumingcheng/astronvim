# 双架构统一发布与验收

本次更新日期：2026-10-26。发布文件为 `astronvim-linux-x86_64.tar.gz` 和 `astronvim-linux-aarch64.tar.gz`，在 Linux/glibc ≥ 2.34 的对应架构上使用。首次启动不需要下载插件或安装 GDB/Python。测试范围和未完成项以包内 [最终验收报告](最终验收报告.md) 为准。

## 一致性范围

两包共用同一套应用源码：`env.sh`、`bin` 中的启动/维护脚本和相对链接、`config/nvim`（含锁文件）、预装插件源码及资源、Neovim 运行时脚本、`scripts`、`vscode`、`docs`、README 和示例源码。共同文件集合、内容 SHA256、权限和链接目标都需一致，不能仅比较相交的几个 Lua 文件。

共同清单为安装根目录的 `source-manifest.json`。原生程序和库、编译后的 tree-sitter parser、工具自带的 GDB/Python 运行时及对应构建元数据保留各架构版本。`platform-architecture` 必须分别为 `x86_64` / `aarch64`；其差异是二进制平台标记，不是两套功能实现。LuaSnip 上游测试中的非本机 parser 二进制不是编辑器使用的 parser，不作为共同源码同步。

已包含此前最后交付的“编译数据库环境配置”补丁：`ASTRO_CLANGD_CDB_DIR` 支持项目根目录相对路径、绝对路径及含空格路径，优先于 `.clangd`，留空保留原自动发现行为。两份包都已包含该补丁的五个完整文件和环境变量入口，无须再单独安装补丁。后续共同更新还包含编辑快捷键、鼠标路由、分割线、滚动条、持续输出增量追加和标准 LSP 字符位置协商；不是仅同步了旧补丁。

## 使用

```bash
tar -xzf astronvim-linux-对应架构.tar.gz -C /目标目录
source /目标目录/astronvim/env.sh
astro-check
astronvim /项目路径
```

例如在 `env.sh` 中设置 `export ASTRO_CLANGD_CDB_DIR="cmake-build-debug"`，目录内须已有 `compile_commands.json`。修改后重新 source 并重启编辑器。重建索引按钮使用已有数据库，不会重新执行 CMake 或编译；新增文件/编译参数变化后需由项目构建系统更新该 JSON。

调试默认使用包内 GDB 17.2。`Esc → 空格 → d → a` 附加进程；F8 单步；Ctrl+F8 普通断点；`空格 d Shift+B` 条件断点。字符串保持 `set print elements 0`。GDB 的嵌入 Python 仅由包装脚本设置，不污染调用 shell 的 `PYTHONHOME`。

## 编辑区常用快捷键更新

支持 Ctrl+C/V/X/A/Z/S、Ctrl+Shift+Z 重做和 Ctrl+Shift+S 保存全部。Ctrl+S 保存当前文件，无名文件询问路径且 Esc 可以取消。Windows VS Code → SSH 使用客户端原生粘贴读取 Windows 剪贴板，复制通过 OSC 52 返回客户端。持续终端标题标记避免切换文件时丢失快捷键接管；客户端扩展同时提供程序标题识别的默认设置。详见 [编辑区常用快捷键](编辑区常用快捷键.md)。

此前阶段已通过 31 项真实 Neovim 编辑操作、10 项终端标题/退出检查及 6 组 Windows VS Code → PowerShell → SSH → Linux 端到端编辑测试。测试 Profile 没有手工设置标题；复制、粘贴操作使用实际 Windows 剪贴板。每份测试的版本边界及当前验收结论见 [最终验收报告](最终验收报告.md)，这些数量不表示当前全部源码已逐项重测。
