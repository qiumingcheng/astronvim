# 历史性能优化说明（2026-09-30）

本节记录 2026-09-30 的历史版本，当前验收状态见 [最终验收报告](最终验收报告.md)。历史原始 JSON 不随总包发布。

当时完成启动选源、实时搜索、状态栏、滚动条、活动栏与调试调用栈的优化，同时加入边框悬停提示。x86 和 ARM 的回归均通过。基线是此前已经加入单步刷新优化的安装，不是最初的慢版本；本轮没有修改编译器、调试器或运行库二进制。

## 第二轮深度分析与优化

在第一轮已交付版本上继续剖析，剩余的确定性瓶颈集中在调试面板：每个短文本片段都走通用 `vim.split`，导致大量临时表和校验；相同调用栈或变量内容被再次呈现时，仍清空高亮并重写缓冲区。第二轮只修改 `data/nvim/lazy/nvim-dap-ui/lua/dapui/render/canvas.lua`，全部数值、完整字符串和可见线程仍正常呈现。

改动包括：直接扫描 CRLF / LF，避免逐个短片段创建通用拆分器；内容和高亮均相同时省略文本、高亮写入；需要更新时一次替换完整内容，省去额外行数查询和尾部删除。按键和鼠标回调每次更新，避免切换帧后操作旧变量。每个缓冲区只保存最近一次快照；文本修改、运行状态清空、提示输入和缓冲区删除均经过失效验证。

ARM / GDB 17.2 的同机 ABBA 对照（基线 → 优化 → 优化 → 基线）结果如下；300 变量场景每侧每种线程数 24 步，小变量场景各 16 步。所有 300 个新增变量仍显示，源码缓冲区不重读，零 DAP 请求错误。

| 场景 | 优化前 → 优化后，中位耗时 | 收益 |
|---|---:|---:|
| 300 个局部变量，1 线程，真实单步及刷新 | 57.55 → 49.54 ms | 13.9% |
| 300 个局部变量，17 线程，真实单步及刷新 | 117.90 → 90.75 ms | 23.0% |
| 少量短变量，1 线程，真实单步及刷新 | 25.67 → 24.74 ms | 基本持平 |
| 少量短变量，17 线程，真实单步及刷新 | 69.53 → 59.47 ms | 14.5% |
| 2,000 行模拟变量画布，有值变化，生成与绘制 | 100.05 → 35.71 ms | 64.3% |
| 2,000 行模拟变量画布，内容相同，生成与绘制 | 99.97 → 8.85 ms | 91.2% |

后两项是画布压力样例，不能当作端到端调试耗时。先预热 75 次，再测 25 次；API 调用计数在计时之后单独测量，避免插桩触发 LuaJIT 重编译而扭曲小场景结果。30 行画布的总耗时也由 0.95 降到 0.50 ms。原始数据与统计见 第二轮汇总（历史记录，留存于验证工作区）。

## 第一轮实测性能

ARM 为 Linux aarch64 / GDB 17.2。真实 UI 与实际调试器参与测试；指标取相应测试样例的中位数，滚动条和拖动取一次完整序列。原始记录见 机器汇总（历史记录，留存于验证工作区）。

| 模块 / 样例 | 优化前 → 优化后 | 结论 |
|---|---:|---|
| 600 文件、400 命中的连续输入关键词搜索 | 225.83 → 122.59 ms | 保留全部命中、类型过滤与取消操作 |
| 19.9 MB / 20,000 项编译数据库的启动同步阻塞 | 171.35 → 0.56 ms | 改为异步分块，找到可用源文件即停止读取 |
| 同一数据库选源完成 | 171.35 → 12.35 ms | clangd 自己仍正常读取数据库并构建全项目索引 |
| 选源阶段 Lua 内存增量 | 41.80 → 1.63 MiB | 不再将整个 JSON 文件及全部对象载入 Lua |
| 200 次位置不变的滚动条刷新 | 63.16 → 11.19 ms | 400 次缓冲区、配置、命名空间重复写入分别降为 0 |
| 两次各 150 个鼠标移动的分割线拖动 | 65,789 → 27,868 字节 | 减少终端输出；最终尺寸相同；手势时长由测试的固定输入间隔决定 |
| GDB 17 线程、短变量连续单步（24 步） | 77.57 → 70.22 ms | 仍获取全部 17 个可见调用栈；变量读取 3 → 2 次 |
| GDB 1 线程、短变量连续单步（24 步） | 24.54 → 25.12 ms | 在本轮运行波动范围内，未出现持续退化 |
| 空项目暖启动 | 80.93 → 80.77 ms | 基本不变；收益主要来自大型项目选源 |

文件枚举仍使用 fd，关键词搜索仍使用 rg，符号/跳转仍由 clangd 提供。没有增加跨次搜索的文件结果缓存，以免新增、删除或修改文件后结果陈旧。600 文件前后结果排序后的 SHA-256 一致；额外 6,000 文件压力检查保留 6,000 个文件结果及 4,000 个关键词命中。

## 复现并修复的原有问题

1. Neo-tree 在 netrw 已禁用时仍清空不存在的 FileExplorer 组，留下 E216。先检查组是否存在，启动错误清零。
2. 目录扫描在关闭文件树后完成，会重新创建侧栏并挤压调试窗口。扫描记录关闭代次，丢弃关闭前的结果；优化前复现（历史记录，留存于验证工作区） / 修复后（历史记录，留存于验证工作区）。ARM 的缩小放大后恢复尺寸也已通过。
3. 从程序输出标题边框拖动时，若按在单步按钮上会先执行单步。水平边框按下后等到释放才判定单击；发生拖动则只调整尺寸。优化前复现（历史记录，留存于验证工作区） / 修复后（历史记录，留存于验证工作区）。按钮单击、八个用途提示仍通过。
4. DAP 解码响应后过早删除在途请求，UI 可能再发一份变量请求。删除时机移到实际回调派发，仍及时拒绝重复回包。优化前复现（历史记录，留存于验证工作区） / 修复后（历史记录，留存于验证工作区）。

## 1.4 万行文件与使用方法

14,000 行注释填充样例的 ARM GDB 连续单步仍复用同一个源码缓冲区，期间 BufReadPost 次数为 0；不会每一步重新读取整个文件。真实复杂宏、模板、首次高亮和 clangd 初次解析仍需要计算。行数本身不是每一步全量载入的开关。原始记录（历史记录，留存于验证工作区）。GDB 的 `set print elements 0`、参数与局部变量、全部配置的业务线程及被断点停住的辅助线程均保留。

安装及回滚见 [执行包说明](性能优化安装.md)。安装完成后重新启动 AstroNvim；使用完整 ARM 包则重新解压并 `source 安装目录/env.sh`，不需要重新编译项目或删掉现有 clangd 索引。
