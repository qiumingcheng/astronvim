# 编辑区常用快捷键

## 1.0.9 焦点规则

Ctrl+Shift+N 已内置到配套 Windows 扩展：单击 AstroNvim 终端后打开工具的文件搜索；单击 VS Code 编辑区后使用 VS Code/IDEA 的绑定。Windows 需更新一次随包 VSIX。手工把 IDEA 全局绑定限制为编辑区的 JSON 示例见 [客户端说明](../vscode/README.md)。鼠标悬停不等于键盘焦点。

适用于普通代码编辑区。ARM 与 x86 使用同一套 Lua 实现和相同的客户端键位配置。

| 快捷键 | 行为 |
|---|---|
| Ctrl+C | 有选区复制选区，否则复制当前行；通过 OSC 52 写入终端客户端剪贴板 |
| Ctrl+V | 普通模式在当前字符之后粘贴；插入模式在当前插入点粘贴；有选区时替换选区 |
| Ctrl+X | 剪切选区；没有选区时剪切当前行 |
| Ctrl+Z | 撤销，不挂起 Neovim 进程 |
| Ctrl+Shift+Z | 重做 |
| Ctrl+S | 保存当前文件；未命名文件先询问保存路径 |
| Ctrl+Shift+S | 保存全部文件 |
| Ctrl+A | 全选当前文件内容 |

以上操作支持普通模式、插入模式和选区。Ctrl+Y 不作为重做快捷键，避免与 IntelliJ IDEA 的删行习惯冲突。文件树、调试面板、搜索输入和内嵌 shell 有各自的操作语义。

## Windows 本地 VS Code 终端 → SSH → Linux

这个链路包含两部分：Linux 端 Neovim 处理编辑，Windows 端 VS Code 处理本机剪贴板。远端 Linux 无需安装桌面剪贴板程序。

1. 把新版包的 `vscode/astronvim-terminal-keys.vsix` 复制到 Windows，在本地安装与该包配套的版本（当前冻结候选为 1.0.8，总包发布状态见 [验收报告](最终验收报告.md)）：

   ```powershell
   code --install-extension .\astronvim-terminal-keys.vsix --force
   ```

   已安装旧版也需要更新一次，并执行 VS Code 的“Developer: Reload Window”。不要在 Linux SSH 终端内用此命令代替 Windows 客户端安装。

2. 在 VS Code 终端中 SSH 到 Linux，照常使用：

   ```bash
   source /你的安装目录/astronvim/env.sh
   astronvim /你的项目目录
   ```

3. 在编辑区按 Ctrl+C，Neovim 将文字经 OSC 52 写到 Windows 剪贴板。在记事本/浏览器等复制后，回到远端编辑区按 Ctrl+V，由本地 VS Code 读取 Windows 剪贴板并经终端粘贴通道发送，支持中文和多行文字。选区会被粘贴内容替换。

启动器 `bin/astro` 为每次运行生成动态 token，经 `ASTRO_VSCODE_TITLE_TOKEN` 传入 Neovim。该会话的 `titlestring` 使用对应的 `AstroNvimPortable:active:<token>` 标记，打开或切换文件时继续保持，让客户端持续识别该编辑器。只有正在运行 AstroNvim 的终端使用此标记；退出后启动器恢复启动前的标题。

客户端扩展提供 `terminal.integrated.tabs.title = "${sequence}"` 作为 VS Code 配置默认值，以便显示并识别程序发出的动态标题，不修改用户 `settings.json`。已有显式标题配置会继续保留；若配置为 `${process}` 等值，终端名称可能一直是 `ssh`，自动接管无法识别。可在 VS Code 设置中把 **Terminal › Integrated › Tabs: Title** 重置为默认，再新建终端启动。

只有 `terminalFocus && portableAstro.active` 时这些临时规则有效；点回本地 VS Code 编辑区、切换普通终端或退出 AstroNvim，会恢复原行为。设置修改前备份在 Windows 当前用户家目录 `.astronvim/vscode-backups/`，退出自动还原，手动恢复仍使用 `astro-vscode-restore`。

安装目录中的 VSIX 文件更新不会自行升级已安装的 Windows 扩展。先退出旧扩展管理的 AstroNvim 会话，再安装配套 VSIX 并重载 Windows VS Code。新组件可迁移旧版保留的备份，保留最初恢复快照；若检测到旧协议仍在运行，会暂停接管并提示。以后每次启动 AstroNvim 的接管与退出恢复均自动执行。

## 普通 SSH 终端

如果终端把 Ctrl+V 原样发送给 Neovim，Ctrl+V 使用编辑器保存的最近复制/剪切内容，不会被之后的普通删除覆盖。外部程序复制的文字需要使用终端自己的粘贴功能；当前 Windows VS Code 未安装组件时可使用 Ctrl+Shift+V。Shift+Insert、右键或其他粘贴键是否可用取决于客户端设置。若终端自身已将 Ctrl+V 设为粘贴，也会走该原生通道。此设计不主动查询客户端剪贴板，避免在不支持读取的 SSH 终端中等待超时。

## 验证范围

历史 1.0.1 客户端的 11 项测试验证了 578 条规则只有 Ctrl+V 的路由改变、其余按键继续转发、升级活动中的 1.0.0、精确恢复原始 BOM/CRLF/注释、配置原本不存在、用户中途修改、动态标题默认值及保留用户显式标题设置等场景；另外 11 项备份/恢复生命周期回归通过。它们使用真实文件与模拟 VS Code API，不代表 Windows 图形客户端经实际 SSH 的端到端实测。1.0.2 引入的多窗口租约和旧协议处理历史范围另见 [客户端说明](../vscode/README.md#102-历史验证范围)。

2026-10-25 已在当时的 Windows 的真实 VS Code 窗口，经 PowerShell、Windows OpenSSH 连接 Linux，完成 6 组端到端验证：Windows 中文剪贴板粘贴、OSC 52 复制回 Windows、选区替换、撤销/重做、磁盘保存及全选/剪切。测试向真实 VS Code 窗口发送键盘事件，并核对 Windows 系统剪贴板和 Linux 文件；不是模拟 VS Code API。测试 Profile 的用户设置为 `{}`，程序标题识别依靠新版扩展默认配置。另有 31 项完整 Neovim 编辑操作和 10 项 PTY 标题/退出检查通过。原始测试记录保留在验证工作区，当前范围见 [最终验收报告](最终验收报告.md)。刷新源码后需重新启动 AstroNvim 加载；仅重 source 不会替换已运行编辑器中的 Lua 模块。

本次验收的主使用方式是 Windows VS Code + 配套客户端扩展 + PowerShell/SSH + Linux。无扩展客户端的插入模式原生粘贴补测属于额外兼容性检查，不作为该主使用方式的必测门槛。
