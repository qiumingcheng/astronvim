# 调试操作

Attach 默认使用包内 GDB 17.2。Windows VS Code 客户端首次安装配套扩展，随后在终端 SSH 到 Linux，source 安装目录的 `env.sh`，在源码项目中启动 AstroNvim；换 Linux 机器只需解压对应架构完整包并 source，不重复执行客户端安装。调试器需要与运行的二进制匹配的源码和调试符号；clangd 的 `compile_commands.json` 用于代码导航，不决定调试器是否能设置断点。

## Attach 与单步

1. 在 Linux 中用 `ps -eo pid,user,comm,args` 核对目标进程。不要沿用其他机器或上次启动的 PID。
2. 打开源码，在有效的可执行代码行按 Ctrl+F8，或单击行号/标记栏，设置普通断点。
3. 按 Esc，再依次按空格 → d → a；搜索当前 PID，选中后回车。进程列表应关闭，程序输出窗显示 Attach 完成标志。失败时查看程序输出和调试日志。
4. 向被调程序发送请求。命中断点后，F8 跳过当前行，F7 进入函数，Shift+F8 跳出，F9 继续。源码缓冲区在单步时复用，不会每步重读整个文件。
5. 数据库暂停期间，新连接或 SQL 等待是正常现象。结束调试且保留数据库进程时执行：

   ```vim
   :lua require("dap").disconnect({terminateDebuggee=false})
   ```

Attach 自动设置 SIGUSR2 正常传递且不暂停、不打印；识别为 gaussdb 时也处理 SIGUSR1。默认 attach 后继续运行，显式 `stopOnEntry=true` 时暂停。GDB 默认 `set print elements 0`；变量很大时，调试器生成和传输完整内容仍有成本。

系统若拒绝 ptrace，先检查错误中的 UID、权限及主机 ptrace 策略。是否调整主机策略应由该环境管理员决定；本工具不会自动更改整机的 `ptrace_scope`。

## 条件断点与删除

按 Esc → 空格 → d → Shift+B，或在行号/标记栏右键，输入 C/C++ 表达式。例如：

```cpp
u_sess != 0 && u_sess->attr.attr_sql.effective_cache_size == 16385
```

不把 `if` 或 SQL 条件写进表达式。变量应在断点所在帧的作用域内，二进制应带匹配的调试符号。x86 上的真实 openGauss 条件测试和 ARM 的当前验证范围见 [最终验收报告](最终验收报告.md)。

回到断点行，再按 Ctrl+F8 或单击标记栏可删除。清空编辑器管理的全部断点：

```vim
:lua require("dap").clear_breakpoints()
```

GDB REPL 的 `info b` 查看断点，`delete 断点编号` 删除调试器中的指定断点；`delete` 无编号删除全部，默认要求确认（`set confirm off` 时不询问），见 [GDB 删除断点说明](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Delete-Breaks.html)。直接在 GDB 中删除不等于更新编辑器持久化的断点清单，日常优先用编辑器删除，以免后续同步或重启重新设置。

本轮 GDB DAP 本地修复会在重新设置或清空前验证缓存对象，解决原生 `delete` 后的 `Breakpoint N is invalid.`。修复保持删除事件、条件表达式和 `print elements 0`；修改后的源码独立通过 6 项原生回归、50 次循环及 25 项 Linux 编辑器回归。源码 SHA、补丁和许可边界见 [GDB 本地修改](GDB-DAP-PATCH.md)。这不改变编辑器持久化断点与原生命令的区别。

## 变量、监视表达式、线程

Scopes 显示当前函数的 Arguments（参数）和 Locals（局部变量），过滤全局变量和寄存器。单击结构体、类或指针节点展开，再次单击收起。继续运行后清空旧位置的数据，新断点或新帧返回后再显示对应变量。

在“监视表达式 / Watches”的空白输入行输入表达式；删除时先点击该区域、按 Esc，将光标移到要删除的表达式上，按 `d`。其默认编辑键为 `e`。也可按索引操作，例如删除第一条：

```vim
:lua require("dapui").elements.watches.remove(1)
```

默认线程名在 `config/nvim/lua/dap_thread_filter.lua` 中配置：`worker`、`TPLworker`、`TPLstream`、`streamworker`、`gaussdb`，按不区分大小写的完整名称匹配。可编辑 `names` 和 Lua `patterns`，重启编辑器生效。需要显示全部线程时：

```bash
source /实际安装目录/astronvim/env.sh
ASTRO_DAP_SHOW_ALL_THREADS=1 astronvim /项目目录
```

即使线程名不在配置内，命中断点并成为当前停止线程时也必须显示。单击栈帧会打开其源码，并显示该帧的参数与局部变量。

## 控制台与窗口

“调试控制台 / REPL”输入命令；“程序输出 / Console”展示输出及 Attach 状态。先按 Esc → 空格 → d → Shift+R 聚焦 REPL，或单击末尾 `dap>`。Enter 执行，↑/↓ 调出历史，Esc 退出输入。

| 操作 | GDB | CodeLLDB |
| --- | --- | --- |
| 查看断点 | `info b` | `breakpoint list` |
| 查看调用栈 | `bt` | `thread backtrace` |
| 查看变量 | `p query_string` | `frame variable query_string` |
| 查看源码记录 | `info sources` / `info source` | `image lookup -vn 函数名` |

窗口之间的分隔线可拖动；内容超出可视区时，通过水平/垂直滚动条查看，不会截断原缓冲区。程序输出按钮悬停提示需要终端支持鼠标移动事件。标签单击切换文件。

## 文件存在但断点提示 No source file named

该提示指调试器没有在目标二进制的调试信息中匹配该源码路径，并不等于 Linux 磁盘上没有这个文件。检查当前二进制是否带符号、是否属于这份源码版本，以及编译时路径与当前路径是否不同。用 `info sources` 查看目标记录的源码；路径不同可按 GDB 的 `set substitute-path 原编译目录 当前源码目录` 配置，并重新设置断点，路径替换规则见 [GDB 源码路径说明](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Source-Path.html)。源码文件存在本身不能证明版本和行号匹配。

临时恢复调试布局可用：

```vim
:lua require("dapui").close(); require("dapui").open({reset=true})
```

这会恢复默认面板比例；不应作为每次单步的操作。Windows 终端完全不再响应输入时，不要把重绘当作统一解决方法：本轮已确认特定 VS Code 的 ACK 边界会导致永久暂停，持久修复与 HOME 恢复命令见 [Windows 终端兼容工具](../vscode/WINDOWS-TERMINAL-FLOW-FIX.md)。该工具只适用于精确匹配的客户端构建。错误记录、`messages` 和 DAP 日志路径见 [README 日志说明](../README.md#日志目录与错误记录)。
