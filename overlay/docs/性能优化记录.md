### Neo-tree：冷启动同步 Git 查询

原 Windows 冷启动的普通 RPC 超过 1500 ms 期限时，现场栈停在 `proc_wait → do_os_system → f_system`。实际 Lua 路径为 `fs_scan.lua:105 → ls-files.lua:39`；对整个外围 worktree 同步执行 `git ls-files --others --ignored` 用时 **4712.751 ms**。同一请求随后返回，`-u NONE` 同链路对照正常，定位为文件树回退查询阻塞主线程。诊断没有改变正式期限或请求协议。

同一原大仓库、旧基线和真实 Windows 链路的后续受控复现记录同步 Git **4966.290 ms**、轻量 RPC 等待 **4947.595 ms**；请求在 Git 执行期间发出，Git 结束后约 1.158 ms 返回。修复候选在同仓库、同客户端及隔离新状态下完成 40 次查询：中位 **0.803 ms**、最大 **478.146 ms**，超过原 **1500 ms** 期限的次数为 **0**，整仓同步扫描调用为 0。`baseline-timeout-root-cause.json` 与 `timeout-fix-confirmation.json` 保留原失败及诊断范围；该跟踪复核是原超时修复证据，不是正式统计性能认证。

冻结修复仅对显示路径异步执行 `git check-ignore --stdin -z`，各仓库分组完成后再渲染，并在回调及调度渲染前检查扫描/关闭代次。保留忽略例外、已跟踪路径、特殊文件名、链接 worktree/嵌套仓库/子模块和错误信息；不通过关闭 Git 过滤或隐藏失败取得通过。精确摘要见 [依赖清单](third-party/依赖清单.json) 的 Neo-tree `local_modifications`。

20 项定向用例及真实 Neo-tree 扫描、渲染、协程目录展开通过。Windows 原冷启动请求在原期限内通过；之后的 `directory_expand` 15 秒超时已定位为测试准备重复打开文件引起的模态提示，修正测试器后原 18 项菜单操作通过。原失败保留，不把测试器问题当作产品加速。**这是指定 GUI 流程的正确性，正式性能和 ARM 实机仍未验收。**
